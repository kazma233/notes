# CSS 结构

把零散的 CSS 收束成有约束的结构：保留 Tailwind 纪律中有用的部分，但不依赖堆满工具类的标记。优先语义化 HTML、小范围的组件作用域，以及一小组共享规则。

## 适用场景

- Tailwind 迁移到原生 CSS
- 为内容站、文档站和中小型产品前端定义 CSS 架构
- 清理 Tailwind 与手写 CSS 混用的代码库
- 制定 token、布局、组件与间距的实用 CSS 规则

## 工作流

1. 先判断问题属于哪一类：token、基础规则、布局、组件作用域、间距、工具类，还是构建配置。
2. 全局样式保持最少。一条规则如果不是明确全站生效，就不要放进 `base`。
3. 每个组件只用一个根类，避免跨组件的样式依赖。
4. 工具类要少且通用。一个类如果表达了产品含义或组件含义，它就不是工具类。
5. 外部间距交给布局/容器控制，不要把 margin 散落在各个子元素上。
6. 先用 `grid`、`flex`、`auto-fit`、`minmax`，再考虑加多个断点。
7. 项目若混用 Tailwind 与手写 CSS，建议收敛到一套，不要长期双轨并存。

## 输出形态

提议或实现 CSS 组织方式时，默认按这样拆分：

- `reset`：只做浏览器差异归一
- `tokens`：颜色、字体排印、间距、圆角、阴影、z-index 刻度
- `base`：一小组真正全局的元素规则
- `layouts`：页面/容器/堆叠/网格等布局原语
- `components`：相互隔离的组件样式
- `utilities`：极少量通用辅助类，例如视觉隐藏

## 判定规则

- 一个值重复出现，就提成 token。
- 一条规则依赖跨多个区块的文档结构，它多半是布局而不是组件。
- 一个选择器需要知道另一个组件的内部结构，停下来重构边界。
- 间距靠局部一次性 margin 修补，就把这个关注点上移到布局层。
- 响应式能用固有布局解决，就不要再加断点。
