# 个人 UI/UX 基线

这是从本人历史会话与项目决策中沉淀的 UI/UX 品味基线。与通用审美冲突时,以本文件为准;与本人当次要求冲突时,以当次要求为准。本人报 UI 问题惯用截图加红框圈定位置,按框内元素定位。

## 稳定:布局不跳动

一切状态切换、数据到达、提示出现的时刻,布局几何都必须稳定。

- 状态提示不占布局空间(本人明确的大忌):反馈挂在高度固定的行内——通常是触发按钮右侧,长文本截断不推挤控件;toast/通知走浮层,不往布局里塞临时状态行。
- 加载/提交状态由按钮自身表达(disabled + spinner + 文案),不加单独的状态条。
- 动态内容(图片、预览、图表)锁在固定尺寸容器里,先占位、数据到达后原地替换,不允许元素出现/消失时推挤周围。
- 长任务的中间状态提前放到终局位置(进度指示器一开始就在它最终所在处),不许完成后结构错位;渐进展示的中间画面与终局布局一致。
- 条件渲染的字段缺席时,布局与之前逐像素一致;空值不留占位行,也不留出额外间隙。
- 单个对象的状态变化用局部标记表达(如该条目标红),不触发整块刷新重排。
- 长文本绝不撑开容器:flex/grid 子项配 min-width 兜底,两条链路都要验证。

## 信息:主信息完整,分级呈现

- 操作对象(路径、命令、模型名等主信息)永不截断——换行、加宽、点击弹详情、直接全展示;截断省略号只用于辅助说明,并配 title 补全。
- 拿不到真实数据的字段连列带 UI 整个删掉,不留永远为空的展示;筛选项必须都有真实产出来源,没有就收窄类型。
- 名实相符:标签必须说真话,发现标签与数据语义不符立即改名并全站统一;不认识的值原样显示原始字符串,不做映射兼容。
- 完整信息只在展开处/使用场景处呈现,常驻入口只放最小标识(如色板代替主题名)。

## 占位预算:chrome 克制

- 常驻区域(chrome)的面积是预算:底栏单行封顶,固定区域宽度不被动态长文本撑开。
- 布局从最窄可用宽度倒推,标签按最窄场景取短;字号放大后极端窄宽的截断属可接受降级,但要心里有数。
- 纵向空间敏感:重复条目(子代理、进程、文件)一行一个堆叠,不铺开多行占满视口;横向滚动只用于筛选 chips/标签条,内容条目不横滚。

## 减法:少一个元素就好一分

- 重复即冗余:同一信息只在一处渲染、同一提示文案不出现两遍、形态雷同的重复元素合并删减——头部和进度行同时显示「扫描中 n 个文件」就是典型 bug。
- 筛选交互用「点击选中、再点取消」,不做「全部 XX」「清空筛选」这类复位按钮;全选做成表头三态复选框,与行内复选框同列。
- 图标按钮不带文字;功能等价的冗余入口删到只剩一个,操作就近挂靠(挂到对象右键或对象本身),不做「先选中再找按钮」。
- 去按钮化:点击值本身完成意图(点击即复制),反馈取最轻形态——文字短暂变色优于图标徽标。
- 添加类入口与内容项同形态(小卡片混排在列表末尾),不放大块专用区域。
- 能省的装饰都省:朴素代码块、小体积依赖(311KB 换 14KB 不犹豫);装饰可以省,完整性不能破。

## 反悔窗口:重动作留退路

- 重动作(连接、删除、批量操作)按下+松开都落在盒内才触发,给「松开反悔」的一层保险;不可逆操作走确认弹窗,弹窗文案说清实际会删什么。
- 命中区域就是视觉盒子,不做隐藏热区;嵌套可点元素互不渗透(点 ✕ 不激活父行)。
- 弹窗内的操作完成前不关闭弹窗:先禁用按钮,操作结束再关。
- 可预期的耗时动作从一开始就给加载态(按钮转圈、骨架屏、加载 modal)并锁住相关输入——等待有反馈,也挡住误操作。
- 频繁比对类交互(试主题、试样式)点击后不收起,收起只由点外部或 Esc 触发。
- 大幅视觉变化只由确定性点击触发,不做悬停预览(整屏换肤跟着指针晃动不可接受)。

## 焦点:无焦点是合法状态

- 打开 ≠ 开始编辑:弹窗打开焦点落作用域根而非第一个输入框,「看一眼再关掉」不该被迫先经过输入;点空白回到无焦点态,关闭后焦点归还来源(如终端)。
- 自动聚焦必须有用户意图佐证(刚点了条目、校验失败定位出错框),否则不抢焦点。
- 切换页面/标签时清掉旧页焦点,键击不能打进看不见的输入框。

## 浮层:不越界、可收起

- 浮层永远在可视区域内:放不下就向对侧翻转,翻转后仍出界就贴边钳制;高度按内容封顶,不能比视口还高。
- 遮罩范围等于交互上下文:菜单/下拉只盖所属面板,模态对话框盖整个窗口(含侧栏底栏)。
- 收起手势统一:点外部或 Esc;同一时刻顶层浮层互斥,由单一归属点管理。
- 不支持的操作明确告知原因(弹窗/禁用+说明),不静默无响应;禁用态用灰化,只读态用软底正常文字——「不可用」和「内容是生成的」是两回事。

## 视觉:安静、语义色、像素锐利

- 状态色尽量只用文字色,避免彩色底和药丸角标;技术标识(模型名、路径、id)用等宽字体 + 弱化色,与内容拉开层次。
- 颜色只承载用户关心的数据维度或语义(红=删除、绿=成功、色阶=大小分档),不承载无关信息、不做装饰;分档色阶用冷暖渐进。
- 颜色一律取语义 token,不硬编码色值;界面 chrome 与内容区同一套取色来源,换主题整体一致。
- 线条用 subtle 档,不抢文本权重;层级归属用树导线这类经典画法表达。
- 像素级锐利:元素间无缝隙白线、无遮挡(半个字符被吞都是 P1)、块元素按几何绘制不留反锯齿毛边。
- 同屏联动视图(面包屑/树/图)始终指向同一位置;UI 不渲染陈旧状态(对象已删除则详情关闭,失败不标成功)。

## 惯例:遵循既有标准

- 遵循平台标准快捷键与编辑键位,修饰键按平台写(Cmd/Ctrl),非标准行为等同 bug;快捷键帮助要穷尽实际存在的所有按键与手势。
- 主题/方案成套提供,深浅都要有,数据逐值对照权威源;新 UI 不发明新规则,只给既有语义加低成本入口(菜单是另一条入口,不新增语义)。

## 交付核对

UI 改动提交前按上列各组逐一核对:稳定(任何状态切换不跳动)、信息(主信息完整)、预算(常驻区不膨胀)、减法(无重复、无冗余入口)、反悔(重动作有退路)、焦点(无焦点可达)、浮层(不越界可收起)、视觉(token 取色无装饰)、惯例(遵循既有标准)。
