# 指定站点规则

`site_sources` 用于从用户指定的网站探索给定时间窗内的文章。每项的 `url` 是发现入口，可为首页、栏目页、站内搜索页或 sitemap；不是 RSS 地址，也不是可推导文章地址的模板。

采集通道、候选生命周期和失败范围以 [collection-rules.md](collection-rules.md) 为准。浏览器中的有效页面内容才可证明页面可用，HTTP 200 本身不足以证明可用。

## 配置

```yaml
site_sources:
  - name: OpenAI News
    url: https://openai.com/news/
    include_patterns:
      - '^https://openai\.com/(index|news)/'
    max_discovery_pages: 100
    max_articles: 20
```

- `name` 与 `url` 必填。
- 未设置 `include_patterns` 时，只允许探索与入口同 host 的 URL；设置后，完整 URL 必须能被任一正则搜索匹配。
- `max_discovery_pages` 默认 100，限制入口、列表、分页、站内搜索和 sitemap 的读取页数。
- `max_articles` 默认 20，限制进入正文读取阶段的候选文章数。按发布时间从新到旧处理；日期不可确认的候选不能挤占时间窗内的已确认文章。

## 发现与范围

只从下列真实页面或链接发现候选：配置入口、页面中的文章列表、可见分页、站内搜索结果和页面已声明的 sitemap。不得拼接 URL、遍历猜测路径，或把外站链接作为本站文章。

发现页必须和文章页分别计数。入口 URL 本身是单篇文章时，直接作为候选；否则它仅用于发现。循环链接、非 HTML 页面、重复链接、超出 host 或 `include_patterns` 的链接记录为过滤或跳过原因。

尊重站点访问控制。遇到登录、付费墙、验证码、robots 限制或明确拒绝访问时停止对应路径，不绕过限制，并记录失败原因。

## 发现闭环

每个指定站点从配置入口开始维护一份待探索路径清单。读取一个发现页后，将其可见的、允许范围内且未访问的分页、列表、站内搜索结果和已声明 sitemap 加入清单；循环链接和范围外链接按“发现与范围”处理。

一个站点的发现阶段只有在以下任一条件满足时才完成：

1. 待探索路径清单为空，且所有已发现、允许范围内的路径都有“已读取”或“路径级失败”结果。
2. 已读取的发现页数达到 `max_discovery_pages`。
3. 已进入正文核验的候选数达到 `max_articles`；按可得发布时间从新到旧选择，日期不可确认的候选不得挤占已确认的时间窗内候选。
4. 入口遭遇来源级访问控制，或全部允许路径都不可读，按 `collection-rules.md` 记录来源级失败。

相关性、质量评分和期望日报篇数只用于候选排序与内容呈现；它们不改变发现闭环的停止条件。每个站点在状态文件中记录已访问的发现路径及结果、`discovery_pages`、`candidates`、`articles_opened` 和终止依据。`truncated_reason` 只能填写上述完成条件中的实际证据，例如“达到 max_discovery_pages=20”或“待探索路径清单为空”，不能用“仅核验高相关候选”等主观描述。

## 日期与正文

每个候选都必须打开文章正文。发布时间按可靠性优先级依次读取：正文页结构化数据的 `datePublished`、`article:published_time`、文章页的 `<time datetime>`、正文附近清晰标注的发布日期。列表页日期、搜索摘要、HTTP `Last-Modified` 和站点首页更新时间不能作为文章发布时间。

无法解析日期、日期超出时间窗、正文不可读、正文过短、付费墙或重复事件的候选写入“异常与过滤”，不得进入“内容”。更新日期只能在正文明确说明为文章发布日期时使用；否则记录为日期不确定。质量评分只影响内容呈现，不影响正文可读且日期合格的候选进入“内容”。

## 状态与汇总

站点源的状态字段和错误归类以 `collection-rules.md` 为准。站点本身没有时间窗内文章属于正常结果。报告中每个纳入条目都使用 `指定站点` ref；发现或正文阶段的候选问题、范围拒绝和上限截断都写入“异常与过滤”。状态记录须满足“发现闭环”的路径与终止依据要求。
